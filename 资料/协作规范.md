# 妖尾公会 · 协作规范（接手 AI 必读）

> 适用：任何接手维护「每日日程表.html」的 AI。与《文件分类与素材接入.md》《云端接入说明.md》并列，本文件为协作流程铁律。

## 一、最高优先级：先给提示词，再执行

- **用户每次提出新需求/新功能时，AI 必须先以聊天文本输出一份完整、可交付其他 AI 的提示词**（覆盖：任务目标、现状代码位置、改动点、约束、验收标准）。
- 提示词**只以聊天文本输出，禁止创建提示词文件**（.md/.txt 等一律不建）。
- 输出提示词后**立即执行**，不等用户确认（除非用户明确要求先看方案）。
- 该规则已同步存入 AI 长期偏好，每次会话自动注入。

## 二、项目铁律（延续）

1. 不重写项目、不新建另一个网页、不安装依赖。
2. 不清除或重置 localStorage、不修改已有任务 ID / 原任务名 / J / EXP / 等级 / 提醒 / 完成记录 / 仓库与历史数据。
3. 修改前完整阅读实际生效的 HTML 与 JS；修改前在 `备份\` 创建时间戳备份（最多保留 5 个，超出删最旧）。
4. 修改 HTML/JS/CSS 后，必须把 HTML 内所有 `?v=` 版本号换成新的唯一时间戳，否则浏览器继续加载旧缓存。
5. 每次改动用 node --check 验证全部引用 JS；必须用浏览器打开实际页面验证（禁止只靠静态检查）。
6. 完成后同步到 `D:\开开的读研记录本\`，校验 SHA-256 一致。
7. 部署云端需用户明确允许后才执行。

## 三、实景对话相关约定（2026-10 新增）

- 小人**悬停**只显示提示，不冒泡对话。
- 小人**点击**只打开互动面板（openGuildMemberInteraction），对话在面板内通过「闲聊」触发。
- 小人**相遇对话**保留（showGuildHallPairDialogue：距离阈值 + 每日每对一次 + localStorage 去重），台词统一读 `代码\guild-encounter-lines.js` 文本库（window.GUILD_ENCOUNTER_LINES / DEFAULT_ENCOUNTER_LINES），文案偏日常、贴合妖尾世界观。
- 扩充文本库时：新增角色对 key（排序后 id 拼接，如 'erza:gray'），每组 3~5 条日常对白，不破坏已有 key。
