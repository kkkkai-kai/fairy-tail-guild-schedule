# 文件分类与素材接入

入口仍是根目录 `index.html` 和 `每日日程表.html`；不要改入口地址或浏览器存档来源。

| 目录 | 内容 |
| --- | --- |
| 代码 | 八个核心脚本、旧素材路径兼容索引 guild-assets.js |
| 样式 | UI样式，图片URL相对于该样式文件使用 ../素材/... |
| 素材/人物/{id-中文名} | 头像、像素小人、状态图、状态表；多人表放“合集” |
| 素材/场景 | 大厅、告示厅、情报角、卷宗架、研读角、吧台、哈比小窝、庆典、天气叠层 |
| 素材/界面 | 边框、功能图标、站点标识、背景剪影、魔法装饰 |
| 素材/道具 | 情报物件、奖励物品 |
| 工具 | 数据核对与迁移工具、素材索引更新工具 |
| 资料/素材审计 | 素材用途和生成审计记录，不是任务存档 |
| 备份/代码 | 最多5代代码回退快照，不压缩 |
| 备份/云端历史、备份/历史恢复报告 | 受保护的历史数据与恢复记录，不适用代码备份轮换 |
| 待人工确认素材 | 不确定身份或用途的素材，不自动删除 |

## 未来图片

1. 新图直接保存到对应分类目录，不留在根目录。保留唯一原图和轻量版，文件名保留人物ID、状态、时段与版本。
2. 相同文件名必须全站唯一。新增人物用“assigneeId-中文名”，不按任务标题重新命名人物。
3. 完成素材后运行 `node 工具/更新素材索引.cjs`，它只更新 `素材/目录索引.json` 与 `代码/guild-assets.js`，不移动文件、不改个人数据。
4. 注册表使用 `guildAssetPath('唯一文件名.png')` 或实际分类路径；HTML/JS路径相对于入口，CSS路径相对于样式文件。索引并不会自动选择或分配人物。
5. 不把未引用当成废弃；历史选图、动态路径与原始表都要审计。同步D盘并发布后核验新路径、缓存与SHA。

## 历史兼容与恢复

旧任务保存的根目录图片名仍由索引解析到新目录，只改渲染路径，不重写任务存档。Service Worker也兼容当前索引中列出的旧图片请求。

恢复v107之前的代码快照时：先保护当前代码，再将快照代码复制回其原始位置；按 `素材/目录索引.json` 的旧文件名→新路径，把所需素材复制回旧版引用位置，或将恢复代码更新到分类路径。不要直接删素材或清空localStorage。后续快照保留实际目录结构，不能只按文件名平铺复制。

密钥目录、D盘独有分享版、未完成迁移资料与用户导出的真实JSON不自动上传公开站点。
