# 文件归类与素材路径

用户2026-10-04要求同类归档并更新代码，未来生成也沿用分类。当前目录从v107起采用中文名称，接手时核验实际目录而非旧根路径。

- 两HTML入口、SW和PWA清单保留根目录，保护原URL、SW作用域与localStorage来源。
- 核心脚本在“代码”，UI在“样式”；“代码/guild-assets.js”是旧图片名兼容索引，先于其他脚本加载。
- 图片在“素材”：人物/{assigneeId-中文名}/头像、像素小人、状态图、状态表；多人表在人物/合集。场景按大厅、告示厅、情报角、卷宗架、研读角、吧台、哈比小窝、庆典及天气叠层归档。界面按边框、功能图标、站点标识、背景剪影；道具按用途。
- 新图直接保存对应目录，保留唯一原图/透明Alpha/轻量版。文件名全站唯一，包含人物ID、状态或时段、版本；不要改身份或把图片名当人物ID。
- 添加素材后运行项目“工具/更新素材索引.cjs”，同步生成“素材/目录索引.json”和“代码/guild-assets.js”。这不是人物自动分配功能。旧任务保存的路径只在渲染时经guildAssetPath解析，不批量改存档。
- JS/HTML图片相对于入口；样式内图片相对于CSS（通常../素材/...）。改路径要查动态拼接、回退、SW CORE_URLS、manifest、CSS、旧任务选图；不要用全局DOM拦截替代真实引用修复。
- 工具在“工具”，审计在“资料/素材审计”；代码备份在“备份/代码”（每端最多5代，按时间而非版本字符串排序），云历史与真实JSON另行保护。不动D盘独有密钥/分享/迁移资料，不公开它们。
- 文件迁移先时间戳备份和精确旧→新清单，检查绝对路径、冲突、重解析点及SHA。后续代码备份保留分类目录结构，不能只复制根目录JS。
- 完成后检查全目录素材存在/哈希、全人物注册表路径、旧保存头像、不同场景/时段/庆典、桌面和手机、SW安装与旧图片URL兼容；D盘与线上分别核验。

项目详细约定见“资料/文件分类与素材接入.md”。未知素材仍放“待人工确认素材”，归类不是删除授权。
